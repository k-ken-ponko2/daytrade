# 海外株（米国株）の情報源 整理

最終調査日：2026-06-13（Webで裏取り。料金・可否は変動するので運用前に再確認すること）

> 30万円の小資金では、単元株100の日本株より**1株単位の米国株**が最低注文額で有利、という判断（README 0章）に伴う調査。
> 日本株は **J-Quants（過去データ）＋ kabuステーション（リアルタイム＋発注）** でほぼ完結するが、
> 米国株は**「過去データ」「リアルタイム」「発注」が別ベンダーに分かれる**のが最大の違い。

---

## 0. 結論（先に要点）

- **過去データ（バックテスト/DEMO用）**：分足が必要なら **Alpaca が最有力**（未入金口座でも10年分の1分足が無料）。日足だけなら Stooq（実装済み）/ yfinance で十分。
- **リアルタイム＋発注（本番）**：**IBKR（Interactive Brokers）に確定（暫定・2026-06-13）**。日本居住者で開設可・API有・端株可・手数料極小。
  （Alpaca はデータ＋執行の一本化が魅力だが日本居住者の可否が未確認のため見送り。状況が変われば再検討。）
- **規制の大変化**：**PDTルール（$25,000の壁）は2026-06-04付で撤廃**。少額デイトレの最大の障壁が外れた。ただし実装はブローカーごとに2027-10まで段階移行、かつ **$2,000未満は無レバ（現金のみ）**。
- **キャッシュ口座の資金回転制限**：T+1決済のため、**売却代金（未決済）を同日中に使い回すと違反（good faith / free-riding）**。高回転デイトレでは実質的な回数制限になる。

## 3. 規制・制度の違い（重要・少額運用に直結）

- **PDTルール撤廃（2026）**：従来は「margin口座で5営業日に4回以上のデイトレ→$25,000維持必須」。これが **2026-06-04 付で撤廃**（SEC承認 2026-04-14）。**口座規模によらずデイトレ回数無制限**に。
  - ただしブローカー実装は**最長2027-10まで段階移行**＝**当面は各社の対応状況を要確認**。
  - **$2,000未満の口座はレバレッジ不可（現金のみ）**。リアルタイムの維持証拠金（時価の25%）は必要。
- **T+1決済＋キャッシュ口座の制限**：2024-05 に T+1 化。キャッシュ口座では**未決済の売却代金を同日に使い回すと good faith / free-riding 違反**。12カ月で3回違反→90日の制限。
  - → **高回転デイトレを少額キャッシュ口座でやると資金回転に上限**。margin口座（PDT撤廃で<$25kでも可）か、回数を抑える設計が要る。
- **為替**：入出金・損益は USD 建て。円→ドル転（ブローカーの為替スプレッド）と**為替損益**が発生。
- **税**：国内証券の特定口座なら外国株も源泉徴収対応。**海外ブローカー（IBKR/Alpaca）は自分で確定申告**（外国税額控除・為替損益の計算）が必要。

## 4. 実装で変わる点（コードへの影響）

| 項目 | 日本株（現状） | 米国株 |
|---|---|---|
| 最低注文単位 | 単元株 100 | **1株**（`MarketProfile.US` 実装済み） |
| 通貨 | JPY | **USD**（`BacktestConfig.for_market` 対応済み） |
| タイムゾーン | JST | **US/Eastern**。当日リセット（VWAP/当日高値）は**取引所ローカル日付**で正規化が必要 |
| 取引カレンダー | J-Quants `/markets/trading_calendar` | **NYSE/Nasdaq**。`exchange_calendars` / `pandas_market_calendars` を使う |
| シンボル | 証券コード（7203） | ティッカー（AAPL）。Stooq は `aapl.us` |
| 調整後価格 | J-Quants Adjustment* | Alpaca adjusted bars / yfinance auto_adjust |
| 半日立会 | 大発会など | 感謝祭翌日・クリスマスイブ等の短縮日 |

**当日リセットのTZ対応（実装済み）**：`compute_indicators(..., session_tz="America/New_York")` を渡すと、
tz-aware なデータを ET 取引日に変換してから日次リセットする（`BacktestConfig.for_market(US)` が自動設定）。
naive なデータは取引所ローカル時刻とみなしてそのまま区切る。NYSE 立会日は `data/calendar.py` の
`nyse_sessions` / `missing_us_sessions`（定例祝日ベース。短縮立会・一度きりの臨時休場は未対応）。

## 5. 推奨スターター構成（この30万円プロジェクト向け）

1. **過去検証**：まず **Stooq 日足（実装済み・無料）** でスイング寄りに骨格確認 → 分足が要れば **Alpaca 無料の1分足（10年）** に差し替え。J-Quants の分足アドオン相当が**無料で賄える**。
2. **執行ブローカー**：**IBKR（IBSJ）に確定（暫定）**。日本居住者で確実＋API有＋端株可。発注は TWS API か Client Portal Web API（kabu と同じく dry_run 既定のアダプタで包む）。
3. **口座種別**：高回転を避けるなら**キャッシュ口座**（PDT非該当・ただしT+1で資金回転に制限）。回転を増やすなら**margin口座**（PDT撤廃で<$25kでも可、ただし<$2,000は無レバ）。
4. **デイ vs スイング再考**：PDT撤廃でデイトレの規制障壁は下がったが、**キャッシュ口座のT+1資金回転制限**と**データ購読コスト**を踏まえると、少額では**スイング〜低回転**の方が摩擦が小さい（先の比較の結論を補強）。
