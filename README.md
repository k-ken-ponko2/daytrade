## 0. 目標と前提

- **元手**：30万円
- **目標（年間）**：年間利益100万円（残高130万円 ＝ 約4.3倍）
- **目標（日次）**：**日利2.5%**をベンチマークとする。
- **対象市場**：当初は日本株。ただし**30万円の小資金では米国株（1株単位）を優先検討**（下記）。
- **手法**：デイトレード／スキャルピングの自動売買
- **認識**：4.3倍は再現性のある手法では極めて困難。達成より先に「退場しないこと」を最優先に設計する。

> **市場の見直し（最低注文数）**：日本株は単元株100なので、3,000円の銘柄は1単位＝30万円＝**全資金が1銘柄に集中**。
> 米国株は**1株単位**で、$150の銘柄なら約2.2万円から買え、30万円を**複数銘柄に分散**できる。最低注文数の壁を外せるのが小資金には有利。
> 中核ロジックは市場非依存なので、`core/markets.py` の **MarketProfile**（`JAPAN` / `US`：最低注文単位・通貨・手数料）を切り替えるだけで対応する。
> 米国株の実運用ブローカーは **Interactive Brokers（IBKR）に確定（暫定）**：日本居住者で開設可・API有・端株可・手数料極小。発注アダプタは未実装。

> **日利2.5%の含意（正直な試算）**：245営業日で複利すると `1.025^245 ≈ 420倍`（30万→約1.2億/年）。
> 当初の年4.3倍を日利換算すると約0.6%/日なので、2.5%/日はその約4倍・複利で約100倍の到達点にあたる。
> 桁が外れて高いため、本プロジェクトでは2.5%を**「無理に最適化して合わせる目標」ではなく「実測して差を突きつけるベンチマーク」**として扱う
> （`BacktestConfig.daily_return_target`＝既定0.025。バックテストが実効日利・目標達成日割合・目標との差を毎回算出）。
> パラメータを2.5%へ過剰最適化することはしない（8章「過剰最適化＝最大の罠」）。

## 2. 証券会社・発注API：kabuステーションAPI（三菱UFJ eスマート証券）

- 個人向けに公式RESTを提供している実質唯一の選択肢。
- REST／WebSocket対応。売買注文・注文状況・保有銘柄・板・歩み値の取得が可能。
- **API利用料・口座維持費・通常プラン料金：すべて無料**。
- 利用には **Professionalプラン（無料）** が必要。
  - 維持条件：信用取引口座を開設し、一定期間に最低1回取引すれば達成（＝下限条件）。
  - 初回利用時は約2ヶ月間無条件で適用される。
  - デイトレで売買していれば自動的に維持される。
- **制約**：kabuステーションアプリ（Windows専用）を起動した状態でないとAPIが動作しない。

> プランは Professional で確定。上位の Premium はAPI利用には不要。

## 4. コスト構造（取引回数との関係）

- 手数料以外のランニングコスト（VPS／クラウド・J-Quants API・kabuステーションAPI）は**すべて固定費**。取引回数では変わらない。
- 唯一かろうじて回数が関わるのは kabuステーション Professionalプランの「最低1回」という下限条件のみ（デイトレなら自動で満たす）。
- **取引回数に直結するのは証券会社の売買手数料のみ**。高回転戦略では、この手数料とスリッページが利益を最も食う要素になる。

## 5. バックテストエンジン方針（Backtrader ＋ NautilusTrader 並行運用）

### 狙い

同一の売買ロジックを2つのエンジンで実装し、結果を突き合わせて二重検証する。

- **Backtrader**：日本語情報・カスタマイズ例が豊富で学習効率が高い。ただし更新は停滞気味（枯れている）。
- **NautilusTrader**：執行メカニクス（注文種別・遅延・板の深さ）に強く、バックテスト→実運用への移行に有利。保守も活発。学習コストはやや高い。

### 設計指針（重要）

1. **ロジックの「単一の真実」を持つ**：売買判定の中核ロジックをエンジン非依存の純Python関数として切り出し、Backtrader と NautilusTrader はそれを呼ぶだけにする。ロジック修正は1箇所で済み、両エンジンの比較が「エンジンの差」だけに絞れる。
2. **結果が完全一致はしない前提**：約定価格・手数料計算・端数処理がエンジンごとに微妙に違う。「ほぼ一致」を目標とし、許容できるズレの範囲を最初に決めておく。
3. **工数はアダプタ層だけに抑える**：中核ロジックを共通化しておけば、増えるのは各エンジンへの接続部分（アダプタ層）だけ。

```
共通ロジック層（エンジン非依存・純Python）
  ├─ 指標計算（pandas-ta / TA-Lib）
  └─ 売買判定関数（シグナル生成）  ← 単一の真実
        ↓ 同じ関数を両方が呼ぶ
  ┌────────────┴────────────┐
Backtraderアダプタ      NautilusTraderアダプタ
  └─ 結果を共通フォーマットで出力 → 突き合わせ比較
```

## 6. 売買ロジックで参照する変数（デイトレ）

### エントリー判定

- 価格と移動平均の位置関係（短期・長期のクロス）
- 出来高の急増（平常時比）
- 板の厚み・気配の偏り
- VWAP（出来高加重平均）からの乖離
- 当日高値／安値の更新
- ボラティリティ（ATR）の水準
- 寄り付きからの値動きパターン

複数を組み合わせて「条件A かつ B かつ C ならエントリー」と定義する。

### 決済判定

- 利確幅（ATRの倍数）
- 損切り幅
- 保有時間の上限（例：◯分で手仕舞い）
- トレーリングストップ
- 引け前の強制クローズ（持ち越さない）

## 7. リスク管理ルール（先に決める）

- **1トレードの最大損失**：資金の5〜7%（約1.5〜2万円）に固定。損切り幅から逆算して株数を決める。
- **損切り**：機械的に実行。「戻るかも」で持ち続けない。
- **利確**：段階的に。+50〜100%で半分利確して原資回収、残りを伸ばす。
- **撤退ライン**：資金が15万円（半分）まで減ったら一旦すべて手仕舞い、手法を見直す。
- **資金性質**：失っても生活に支障のない余剰資金であること。
- **信用取引**：最初は現物で優位性を確認してから。いきなりフルレバは退場が先に来る。

---

## 8. 検証時の心構え

- バックテストは「儲かる証拠探し」ではなく **「どの相場で壊れるか探し」** のつもりで行う。
- **過剰最適化（カーブフィッティング）が最大の罠**。短期間データで効いただけの偶然を優位性と誤認しない（10年分・複数の相場局面で検証する理由）。
- 手数料・スリッページを必ずコストに含めて検証する。

---

## 9. 進め方（フェーズ）

1. **接続確認**：J-Quants Free でデータ取得の最小コードを動かす（自宅PC・0円）。
2. **ロジック明文化**：デイトレの売買ルールを検証可能な形で厳密に定義する。
3. **共通ロジック層の実装**：指標計算＋売買判定をエンジン非依存の純Python関数として書く。
4. **二重バックテスト**：Backtrader と NautilusTrader それぞれに共通ロジックを接続し、手数料・スリッページ込みで検証 → 両者の結果を突き合わせる。本格検証時のみ Standard＋分足を契約し、終了後に解約。
5. **フォワードテスト**：ペーパートレード（模擬取引）で数週間〜数ヶ月、実環境の挙動を確認。
6. **少額の実資金**：優位性が確認できてから小さく開始。
7. **段階的に拡大**：勝てているときだけロットを上げる。本番常時稼働になったら国内VPSへ移行。

設計の核（README 5章）：売買判定は `core/signals.py` の `decide()` に集約し、
Backtrader / NautilusTrader アダプタはそれを呼ぶだけにする。
ロジック修正は1箇所で済み、各エンジンの差分が「エンジンの差」だけに絞れる。

### 決済ロジック（README 6・7章）

`decide()` は損切りに加え、以下を `StrategyParams` で切替できる（None で無効＝従来動作）:
- **トレーリングストップ** `trailing_stop_atr_mult`：高値からこの ATR 倍ぶん下げたら手仕舞い（利を伸ばす）
- **段階的利確** `scale_out_atr_mult` / `scale_out_fraction`：第1目標で一部利確して原資回収、残りを伸ばす
- **撤退ライン** `BacktestConfig.retreat_drawdown`：評価額が初期資金から指定ぶん減ったら全手仕舞いして以後停止（0.5＝半減で撤退）

トレーリングと段階利確のロジックも core 関数（`open_position` / `update_trailing_stop`）に集約し、
Backtrader / NautilusTrader アダプタが同じものを呼ぶ。

### ライブ実行層（kabuステーションAPI）

本番の発注・板取得は `live/kabu.py`（Windows専用アプリ起動が前提・ローカル REST）。安全側に倒し、

を指定したときだけ。認証情報は `.env`（`KABU_API_PASSWORD` / `KABU_TRADE_PASSWORD`）から読む。

### データ取得パイプライン（free 日足）

日足の取得 → ローカルキャッシュ（parquet／無ければCSV） → バックテスト用 OHLCV 整形までを束ねる。
キャッシュには J-Quants の生レスポンスを保存し、調整後／生の選択は読み出し時に行う（再取得不要）。

```bash
# 1銘柄を取得・キャッシュして OHLCV（既定=調整後）を表示。--raw で生の価格
PYTHONPATH=src python scripts/fetch_jquants_data.py fetch 7203 --from 2024-01-01 --to 2024-03-31

# 売買代金（流動性）で上位銘柄をスクリーニング（指定営業日の平均）
PYTHONPATH=src python scripts/fetch_jquants_data.py screen --dates 2024-01-15 2024-01-16 --top 30

# キャッシュ済み日足の欠損営業日チェック（取得漏れ検出）
PYTHONPATH=src python scripts/fetch_jquants_data.py check 7203 --from 2024-01-01 --to 2024-03-31
```

**価格種別（調整後 vs 生）**：株式分割等で生の株価は分割日に不連続になり、指標・損益計算が壊れる。
これを遡って補正・連続にしたのが調整後価格で、**バックテストは調整後（既定）が正しい**。
「当時の実際の値段・単元あたり必要資金」を見たいときだけ `--raw`（`adjusted=False`）を使う。
流動性スクリーニングの売買代金は、その日の実際の代金 `TurnoverValue`（生）で評価する。

### 市場プロファイルと海外株（米国株）

中核ロジックは市場非依存。`core/markets.py` の `MarketProfile` で最低注文単位・通貨・手数料を切り替える。

```python
from daytrade.core.markets import US, JAPAN
from daytrade.backtest.engine import BacktestConfig

US.min_position_value(150.0)        # 150.0  … 米国株は1株=$150から
JAPAN.min_position_value(3000.0)    # 300000 … 日本株は単元100株=30万円
cfg = BacktestConfig.for_market(US, initial_cash=2000.0)   # lot_size=1/USD で同じエンジンを回す
```

米国株の過去データは無料の Stooq 日足、または任意のCSVから:


### ウォークフォワード検証（過剰最適化の検出）

パラメータを過去区間（イン・サンプル/IS）で最適化し、その先の未知区間（アウト・オブ・
サンプル/OOS）で評価する。**ISは良いのにOOSで崩れる＝過剰最適化**（README 8章の「最大の罠」）。
区間をずらして繰り返し、IS-OOSのギャップと相場局面別の挙動を見る。

```bash
PYTHONPATH=src python scripts/walk_forward.py --all-regimes --days 40 --train 10 --test 5
```

出力は各区間の IS%／OOS%／OOS取引数／勝率と、局面別（mixed/trend_up/trend_down/chop）の要約。
**合成データには本来優位性がないため、OOS平均が0以下になり「採用しない」と出るのが正しい挙動**
（検証器が偽の優位性を作らないことの確認）。実データに差し替える際は df を `to_ohlcv()` の出力に置換する。

### 段階導入のメモ

- 指標：いまは pandas/numpy 実装。`requirements.txt` の `pandas-ta` / `TA-Lib` を有効化すれば差し替え可能（入出力の形は不変）。
- 分足の実データ：free では日足のみ。デイトレ用の分足は Standard＋分足アドオン（5章）。本格検証時のみ契約し、終わったら解約する方針。
- エンジン：`backtrader` はデモ・二重検証で使用（`pip install backtrader`）。`nautilus_trader` はアダプタ実装済み（重い依存のため任意導入。未導入時は関連テストを自動スキップ）。
- ライブ：`live/kabu.py` は Windows のkabuステーションアプリ起動が前提。実発注は不可逆なので検証ポート＋dry_run から。
